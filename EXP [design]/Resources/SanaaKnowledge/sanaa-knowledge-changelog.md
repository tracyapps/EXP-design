# Changelog — Sanaa Design Knowledge Pack

All notable changes to the knowledge pack. Version lives in each module's frontmatter and in the index.

## 2.0.0 — 2026-08-31
- **directions → v2.0.0** (replaces 1.0.0): concrete divergence vocabulary — nine genome axes with from→to values, silent candidate enumeration, and a sibling-divergence check — so a quick variations request cannot collapse into pixel-shuffles of one idea.
- **procedural-tasks (new)**: deterministic measure→derive→replicate builds, repeated structures, subject-grounded placeholder data, and auditable arithmetic.
- **bulk-adjustments (new)**: compact/spacious density variants and batch edits that preserve layout structure and content floors.
- **a11y-applied (new)**: applied contrast, target-size, ARIA-role, and focus workflows. Its WCAG 2.2 facts were re-verified 2026-08-31 against official W3C sources; the target-spacing and focus-obscuring language was corrected during integration.
- **style-profile (new, current-behavior adaptation)**: document/session style grounding and honest no-memory responses. The delivered future Style Profile/editor/preferences-log contract remains clearly labeled as unshipped rather than teaching the agent to promise a nonexistent v2.4 surface.
- INDEX when-to-load table and module list updated; all other v1 modules unchanged.

## 1.0.0 — 2026-08-29
- Initial launch: 11 knowledge modules + INDEX + 8 style vocabularies (see INDEX for the map and when-to-load table).
- a11y-foundations standards facts verified 2026-08-29 against primary sources (w3.org, section508.gov, ada.gov, ecfr.gov, federalregister.gov, digital-strategy.ec.europa.eu, eur-lex.europa.eu, GDS/DWP, Deque) — re-verify before standards claims reach product copy.
- get_design_facts (computed design facts: contrast pairs, text/target sizes, spacing inventory, fonts) arrives with FEAT-055 in the same release; until it ships, modules direct the agent to explicit document reads instead of estimates.
- Every rule is a proposal with a tradeoff. Nothing in this pack creates a canvas write path — all changes stay behind apply_edits, the switches, and per-document consent (SANAA-PLAN §4/§6).
